## 1. Provenance Chain Narrative in Bayesian Section

**Location:** Phase 4.1 (Trait Inference Engine Upgrade) → Bayesian Inference Hooks

**Add after the Bayesian formula:**

### Provenance Weight Calculation

The `evidence_weight` term in the Bayesian update formula is not a simple scalar — it's a composite score derived from three provenance dimensions:

```python
evidence_weight = source_credibility × recency_factor × consistency_score

where:
  # Source Credibility (0.0-1.0)
  source_credibility = {
      "direct_user_input": 1.0,        # User explicitly states trait
      "behavioral_observation": 0.85,  # Inferred from User actions/choices
      "third_party_report": 0.7,       # Relationship partner observation
      "historical_inference": 0.5,     # Carried over from prior system version
      "speculative_model": 0.3         # LLM inference without strong evidence
  }[evidence.source_type]

  # Recency Factor (exponential decay, half-life: 90 days)
  days_since_evidence = (now - evidence.timestamp).days
  recency_factor = exp(-days_since_evidence / 90)
  # Note: Never drops below 0.1 (old evidence still informs, just weighted lower)

  # Consistency Score (alignment with existing evidence)
  existing_RR = trait.current_RR
  evidence_RR = evidence.proposed_RR
  consistency_score = 1 - abs(existing_RR - evidence_RR)
  # High consistency (evidence agrees with prior) → weight near 1.0
  # Low consistency (evidence contradicts prior) → weight near 0.0
  # Low consistency also triggers tension marker (see Phase 4.2)
```

**Tuning Guidance for Engineers:**

- **High-Credibility Sources:** Direct user input and behavioral observations should dominate. If `source_credibility` for these drops below 0.8, recalibrate.
- **Recency Decay:** 90-day half-life is initial guess. Monitor trait stability: if traits fluctuate wildly, shorten half-life (e.g., 60 days). If traits too sticky, lengthen (e.g., 120 days).
- **Consistency vs. Contradiction:** Low `consistency_score` (<0.3) should elevate `tension_score` (Phase 4.2) and trigger Head Coach probing. Don't suppress contradictions — surface them.

**Why This Matters:**

Provenance weighting ensures that not all evidence is treated equally. A User's direct statement ("I'm an introvert") should override a speculative LLM inference. Recency decay prevents ancient, possibly outdated evidence from dominating. Consistency scoring surfaces contradictions early, feeding the tension framework.

## 2. Meta-Trait Retention and Decay Rules

**Location:** Phase 1.4 (Lightweight Holistic Review Hook) → Meta-Trait Output

**Add after meta-trait container schema:**

### Meta-Trait Lifecycle Management

Meta-traits generated by holistic review are **temporary by design** — they're hypothesis containers, not permanent personality markers. Here's the lifecycle:

**Creation (Day 0):**
- Holistic review detects cross-User pattern (e.g., "Users with high empathy scores prefer collaborative communication")
- Writes meta-trait to temporary container: `meta_traits/empathy_delta = +0.35` (User is 0.35 above population mean)
- Sets TTL: 30 days from creation timestamp
- Logs provenance: which holistic review run, which Users contributed to pattern, anonymized aggregate statistics

**Active Period (Day 0-30):**
- Meta-trait is **readable** by Inference Engine (Phase 4.1) for correlation training
- Contributes to Curiosity Engine (Phase 4.3) scoring: high `empathy_delta` + low RelationshipDNA RR → elevated curiosity for relationship traits
- Visible in Dev Mode with "Temporary" badge and countdown timer ("Expires in 18 days")

**Decay Trigger (Day 30):**
- **If meta-trait reinforced by new evidence** (holistic review recomputes and finds same pattern still holds):
  - TTL extended by 30 days
  - Provenance log updated with "reinforcement" event
  - Meta-trait remains temporary (does not auto-promote to permanent)

- **If meta-trait NOT reinforced** (pattern no longer detected or User data insufficient):
  - Meta-trait marked for expiration
  - **Automatic curiosity spike:** Curiosity Engine elevates related traits (RelationshipDNA in empathy example) by 0.2× for 7 days
    - Rationale: "We used to see a pattern here, but it's fading — let's explore if it's changed or if we need more data"
  - After 7-day curiosity spike, meta-trait purged from container
  - Provenance archived in Dev Mode with tombstone marker: `{status: "expired_unreinforced", expiry_date: "2025-11-05"}`

**Manual Promotion (Optional):**
- Developer can manually promote meta-trait to permanent container via Dev Mode if pattern proves highly predictive
- Requires justification note (logged in provenance)
- Promoted trait loses "temporary" badge, no longer subject to TTL

**Why This Matters:**

Meta-traits are experimental. If we permanently commit every holistic review inference, we risk polluting ReDNA with stale patterns. The decay → curiosity spike → purge cycle ensures the system continuously validates its assumptions and explores when patterns fade.
